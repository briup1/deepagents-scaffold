# 编码规范

> 本文件是 AI 生成代码的评判标准；项目根 `CLAUDE.md` 红线的细则在这里展开。

## 一、通用规范

### 1. 命名规范
- Python：模块/函数/变量 snake_case，类 PascalCase，常量全大写下划线。
- TypeScript：组件 PascalCase，hooks `useXxx`，api 函数 camelCase，类型 `XxxResponse`/`XxxParams`。
- 数据库表/字段：小写下划线，无前缀（❓ 缺省决定，维持现状）。
- 命名必须来自 `wiki/领域术语.md`，禁止自造同义词。

### 2. 代码格式
- Python：ruff（line-length=120, target py312），提交前 `ruff check src tests && ruff format src tests`。
- TypeScript：tsc 严格模式，`npm run build` 含类型检查。
- 单函数不超过 80 行 ❓，超过即考虑拆分。

### 3. 魔法值
- 禁止裸写魔法数字/字符串；必须提取为有名常量或枚举，并说明业务含义。
- 配置值（超时、阈值、限额）一律进 `config.yaml`，禁止散写代码里。

### 4. 空值处理
- 入参在信任边界（API 入口、外部数据）必须校验（Pydantic / zod）。
- 空值有明确的失败或降级路径；`except` 禁止静默 `pass`（红线 4），忽略必须留下日志或注释说明理由。

## 二、后端规范（Python / FastAPI）

### 1. Router 层（api/routers/）
- 只做路由、参数校验、调用运行时/服务、构造响应（Pydantic `response_model`）；**禁止业务逻辑**。
- 错误响应统一结构 `{detail, request_id, type}`，由 `ErrorHandlerMiddleware` 兜底；路由内禁止裸 `try/except` 吞掉异常返回 200。

### 2. 服务与装配层（runtime/、core/）
- Agent 装配逻辑唯一归属 `runtime/agents.py`；新组件（工具/中间件/子 Agent）按"plugins 或 infra 实现 → config.yaml 注册 → 工厂装配"路径接入，禁止在工厂里硬编码。
- SQLite 写操作边界清晰：repository 方法内 commit，多步写入失败必须回滚，禁路由函数里直接写库。

### 3. 异常处理
- 维持现状：不引入业务异常类体系；底层异常由 `ErrorHandlerMiddleware` 统一捕获，记录 `logger.exception`（含 request_id 与堆栈）后返回统一结构（❓ 用户已确认维持现状）。
- 面向用户的信息进 `detail`，排查细节进日志，不进响应体。
- 日志必须结构化（JSON 格式由 `infra/logging/` 配置），关键操作可审计。

### 4. 数据访问（infra/history、infra/artifacts）
- 表结构变更必须写在 repository 的 `migrate()` 中（`CREATE TABLE IF NOT EXISTS` + `PRAGMA user_version` 递增），禁止外部脚本改库。
- 查询必须走索引意识：`messages`、`threads`、`extraction_tasks`、`artifacts` 已有索引见 `wiki/数据模型.md`，新查询字段先评估索引。
- 多用户数据隔离：所有按 thread/artifact 查询必须带 `user_id` 过滤（403 非属主 / 404 不存在语义见 `wiki/接口协议.md`）。

### 5. 工具与中间件规范
- 自定义工具放 `plugins/tools/`，必须 `async` + 关键字参数 + 类型注解，在 `config.yaml` `tools:` 注册。
- 自定义 Agent 中间件继承 `AgentMiddleware` 基类，在 `config.yaml` `middleware:` 注册（别名或完整导入路径）。
- HTTP 中间件按 `api/app.py` 既定顺序注册（CORS → Auth → RequestId → RateLimit → Logging → ErrorHandler），新增需说明包裹位置。
- 本项目无 Redis / 消息队列：缓存与 MQ 小节不适用，禁止引入（如需引入先走专家评审）。

### 6. 沙箱与代码执行
- 用户代码只能在 `infra/sandbox/`（bwrap / subprocess）中执行，超时 60s、内存 512MB（`config.yaml execution_sandbox`）；禁止 `eval`/`exec` 裸执行用户代码。

## 三、前端规范（React / TypeScript）

### 1. 语法规范
- TypeScript 严格模式：未知结构用 `unknown` + 类型收窄，禁止 `any` 逃逸（红线 6）。
- React 函数组件 + hooks；禁止 class 组件与旧式生命周期写法。

### 2. API 层（src/api/）
- 所有请求走 `apiFetch`/`apiFetchJson`（红线 7）：统一注入 `X-API-Key`、401 全局登出。
- 响应类型与 `wiki/接口协议.md` 的结构对齐；新接口先定义类型再写调用。

### 3. 组件规范
- 组件单一职责；页面组件（App/Sidebar）组装子组件，数据逻辑下沉 hooks/。
- props 必须声明类型；跨组件通信用 React context（如 `GenerativeUIContext`），禁止乱用全局事件。

### 4. 样式规范
- 全局样式集中 `index.css` + Tailwind；组件样式隔离，禁止污染全局。
- 颜色/间距用 Tailwind 语义类，禁止散写硬编码色值。
- 禁止 `console.log` 残留提交（⚠️ 技术债：FileUploadDropzone.tsx 现存 3 处）；调试日志提交前删除。

## 四、测试规范（与 skills/单元测试编写 联动）
- 新功能必须带单元测试；修复 bug 先写复现测试（根 CLAUDE.md 硬性要求）。
- 后端：pytest + asyncio_mode=auto，fixture 集中 `tests/conftest.py`，FastAPI 用 `TestClient` 上下文管理器（lifespan 依赖）。
- 前端：Vitest + RTL + jsdom，测试文件 `*.test.ts(x)` 与被测文件同目录或 `__tests__/`。
- Mock 外部依赖（LLM/沙箱/文件系统），测试可重复、无环境依赖。
