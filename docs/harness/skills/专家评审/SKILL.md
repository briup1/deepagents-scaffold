# 专家评审技能


## 概述
重大变更（新领域、核心链路改造、多用户数据/沙箱安全相关）在代码审查之上再加一层的深度评审。

## 触发条件
- 用户明确要求评审；或变更触及核心链路（`/agent` SSE 流式对话、数据抽取流水线、历史会话持久化）；或引入新技术/新中间件/新通道。

## 评审重点

### 1. 领域与分层符合度
- 新代码落在正确的层（api/runtime/core/infra/plugins）？依赖方向是否仍然单向（test_layering.py 会兜底，但评审应提前发现）？
- 命名与 `wiki/领域术语.md` 是否一致？

### 2. 并发与一致性
- SQLite 多步写入的 commit/rollback 边界；async 任务（SSE 流、沙箱执行、aiosqlite）是否有泄漏的竞态。
- 多用户数据隔离：新查询是否都带 `user_id`？403/404 语义是否符合 `wiki/接口协议.md`？

### 3. 安全
- 用户代码执行路径是否全部过沙箱？配置中新引入的密钥是否走 `$ENV_VAR`？
- 输入是否经 InputGuardrail / Pydantic / zod 校验？

### 4. 扩展性考量
- 本次方案三个月后最可能怎么变？变更成本是否可接受？
- 有没有"为了不存在的需求"做的过度设计？（有就删掉）

### 5. 技术债评估
- 本次变更是还债还是欠债？欠债必须显式记录并给出偿还路径（对照 `CLAUDE.md` ⚠️ 项）。

## 输出
- 评审意见：阻断性问题 / 建议改进 / 认可通过，附理由。
