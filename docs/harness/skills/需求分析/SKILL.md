# 需求分析技能


## 概述
拿到需求后先分析再动手，把模糊处、影响面、冲突点在编码前暴露。

## 触发条件
收到新需求、需求变更、或 bug 报告时自动激活。

## 执行步骤

### Step 1: 需求解析
- 用自己的话复述需求（业务目标、用户角色、验收标准）。
- 列出所有假设；不确定的点显式标出。

### Step 2: 业务影响分析
- 对照 `wiki/业务模型.md`：涉及哪些领域（网关与 Agent 运行时 / 数据抽取 / 历史会话 / 工件存储 / 通道）？触及哪条核心链路（`/agent` SSE 流式对话 / 抽取流水线 / 历史持久化）？
- 新实体/新状态 → 准备对 wiki 的更新补丁。

### Step 3: 技术影响分析
- 对照 `wiki/接口协议.md`、`wiki/数据模型.md`：改哪些接口/表？`migrate()` 是否要变更？
- 对照 `rules/`：是否触及红线（async 工具、分层方向、类型注解、apiFetch 等）或需要新规则？
- 跨前后端改动：先确认接口契约（URL、方法、请求/响应体）。

### Step 4: 冲突检测
- 需求之间、需求与现有规范之间、需求与技术债（见 `CLAUDE.md` ⚠️ 项）之间的冲突，逐条列出。

### Step 5: 输出
- 一页纸分析：理解 + 影响面 + 冲突 + 待确认问题清单。
- **用户确认后才进入编码实现。**
