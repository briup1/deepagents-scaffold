# 单元测试 CI 技能


## 概述
在持续集成阶段强制执行测试与质量门禁，拒绝低质量代码合入。

## 触发条件
代码推送 / 提交前由开发者执行；项目当前无 CI 流水线，本技能以本地门禁形式执行（`rules/开发流程规范.md` 第 3 节自检命令）。

## 执行标准

### 1. 覆盖率门槛 ❓（新提议，已获原则同意）
- 核心模块（`src/scaffold/api`、`src/scaffold/runtime`、`src/scaffold/infra`）行覆盖率 ≥ 60%。
- 新功能必须带测试；本次变更涉及的模块不允许覆盖率为 0。
- 当前 pytest/vitest 均未接入覆盖率插件，接入后启用数字门禁；未接入前以"新逻辑有测试"人工把关。

### 2. 测试执行规范
- 外部依赖全部 Mock，禁止单测依赖真实 LLM / 沙箱 / 网络。
- 断言严格：比较期望值并带明确错误信息；禁止模糊断言（如仅 `assertIsNotNone` / `toBeTruthy`）。

### 3. 坏味道检查（Anti-Patterns）
- 无断言测试视为无效测试，直接失败。
- 生产分支禁止使用跳过标记（`pytest.mark.skip` / `it.skip` 等）；确需跳过必须在用例旁注释理由。
- 单个测试方法过长（>80 行）→ 拆分，逻辑必须单一。

### 4. 测试报告输出
- 运行结果逐文件列出；覆盖率报告接入后高亮未覆盖行。
- 未过门槛 → 禁止合入，并提示开发者补充哪些用例。

## 输出
- 通过 / 失败 + 测试摘要 + 未覆盖热点清单。
