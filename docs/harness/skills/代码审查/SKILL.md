# 代码审查技能


## 概述
提交前的强制自查/互查，三个维度：红线、规范、坏味道。

## 触发条件
代码完成、提交或提 PR 前自动激活。

## 审查维度

### 1. 安全红线检查（一票否决）
- 逐条对照项目根 `CLAUDE.md` 红线：async 工具 + kwargs、分层依赖方向、密钥走 `$ENV_VAR`、except 不静默吞错、Python 类型注解 / 前端禁 any、apiFetch 统一出口、错误响应统一结构、日志无敏感信息、单函数 ≤80 行、AI 文档用中文。
- 任何一条违反 → 打回，不进入下一维度。

### 2. 性能与规范检查
- 对照 `rules/编码规范.md`：命名（术语表）、空值、魔法值、migrate 规范、索引与 user_id 隔离、沙箱执行边界、前端组件职责与样式。
- API 响应结构是否与 `wiki/接口协议.md` 一致。

### 3. 代码坏味道检查
- 重复代码、超长函数、深层嵌套、注释掉的死代码、模糊命名、`console.log`/`print` 残留。
- 发现坏味道优先简化，而不是加注释解释。

## 输出
- 审查结论：通过 / 打回（附问题清单：位置 + 违反条款 + 修改建议）。
