# 领域术语表（统一语言）

> 本表是命名的唯一依据：代码、接口、文档中的概念必须与本表一致，禁止同义词并存。

## 1. 业务术语
| 术语 | 英文/代码命名 | 定义 | 出处 |
|------|--------------|------|------|
| 会话/线程 | Thread（thread_id） | 一次连续对话的上下文单元，绑定 Agent 与属主 | 历史会话域 |
| 消息 | Message（message_id） | 线程内的一条角色消息（user/assistant/system/tool） | 历史会话域 |
| 工件 | Artifact（artifact_id） | 上传或生成的文件单元，五类：upload/script/extraction/report/normalized | 工件域 |
| 抽取任务 | ExtractionTask（task_id） | 一次"生成脚本→执行→验证"的完整抽取过程 | 数据抽取域 |
| 抽取模板 | ExtractionTemplate（template_id） | 验证通过的 目标+脚本+结构指纹 复用单元，按用户隔离 | 数据抽取域 |
| 规范化 | normalize（artifact_type=normalized） | 合并单元格拆分、删除线过滤的预处理 | 数据抽取域 |
| 画像 | Harness Profile | config.yaml `profiles.harness` 中定义的 Agent 行为配置（系统提示词、排除项、技能） | 运行时域 |
| 通道 | Channel | 飞书/Slack 等 IM 接入（默认关闭） | 通道域 |
| 记忆 | Memory（storage_path=./data/AGENTS.md） | 跨会话持久化的 AGENTS.md，由 MemoryMiddleware 注入 | 运行时域 |

## 2. 状态定义

### 2.1 ExtractionTask 状态
| 状态 | 值 | 含义 | 允许迁移 |
|------|----|----|----------|
| 目标确认 | goal_setting | 任务创建，需求待明确/脚本未生成 | → code_generated |
| 脚本已生成 | code_generated | 脚本就绪，可 iterate / finalize | → validating |
| 验证中 | validating | finalize 落盘后等待验证结果 | → success / failed |
| 成功 | success | 验证通过，结果工件可用 | 终态 |
| 失败 | failed | 验证未通过，按建议迭代或重生成 | → code_generated（重新生成） |

> 来源：`infra/history/models.py` TaskStatus Literal，已与代码逐个值核对。

## 3. 技术术语
| 术语 | 含义 | 备注 |
|------|------|------|
| AG-UI | Agent-User Interaction 协议，SSE 事件流 | `@ag-ui/client` HttpAgent / ag-ui-langgraph |
| harness | 本规范体系（docs/harness/） | bootstrap 生成、sync 维护 |
| 红线 | 宪法中不可违反的约束 | ✅/⚠️/❓ 三分类 |
| request_id | 链路追踪 ID，HTTP 中间件注入 | 错误响应必带 |
| user_id | 多用户隔离键，auth 决定 | default 为本地兼容值 |

## 4. 命名约定
- 代码命名优先用术语表"英文/代码命名"列；新增概念先登记本表再写代码。
- 后端 snake_case，前端组件 PascalCase、hooks `useXxx`。

> 维护：术语由 harness-sync 反补；发现同义词时合并并全局改名。
