# 需求 0001：P0 三道闸门 + 抽取模板复用

## 需求重定义

**原始诉求**：在 Excel 抽取与分析三阶段能力已就绪的基础上，补齐四个 P0 缺口——多用户数据隔离（R1）、生产级沙箱（R2）、韧性中间件启用（R3）、抽取目标模板复用（R4），使系统达到可对外交付的状态。

**最终目标**：提出需求的人要的不是"四个功能"，而是一个结果——**把系统从单机 Demo 推进到可安全地面向真实多用户演示/交付**：数据不互见、生成的代码伤不到宿主机、模型抖动不死 Agent；同时消除报价单这一最高频场景中"每个会话重复对齐抽取目标"的体验损耗。

**异议**：整体路径**已求证为最佳路径**——三道闸门均是对已核实阻断级缺陷的正面解法；R4 直击报价单类文件格式高度重复的场景，且误判方向保守（宁走完整流程不套错模板）。四件事打包为一个需求与 PRD 自带的 M1–M4 里程碑拆分不冲突，实施按里程碑拆工单。

需求确认过程中形成三条结论（覆盖原 PRD 中的方案层表述，具体实现一律留待方案设计阶段）：

1. **`/agent` 等全部业务端点必须纳入身份校验**（需求方已确认）。现状 `AuthMiddleware` 对 `/agent` 整路径豁免；若维持豁免，任何人持他人 `threadId` 即可驱动 Agent 读取其会话历史与工件，R1 隔离从 Agent 通道被整体绕过，且 Agent 工具层的 user_id 过滤将无从依附。至于凭证如何传递（前端连接层改造），属于方案设计范畴。
2. **沙箱实现方案不在需求阶段指定**。约束：目标部署环境当前无 Docker。需求只规定隔离底线（文件系统、网络、资源限额、结构化错误）与验收标准；docker / e2b / 其他隔离方案的选型留待方案设计阶段。
3. **存量数据不做迁移，启用隔离时直接删除**（需求方已确认），移入 Out of Scope。

**重定义后的需求**：以"可安全对外交付的多用户 Excel 抽取分析系统"为目标，落地四件事：用户级身份认证与数据隔离（含 Agent 工具层过滤）、抽取脚本的隔离执行环境、默认启用的模型/工具韧性能力、归属用户的抽取模板保存与复用。验收以 PRD 四个 G 级目标为准。

## 用户故事

1. As a **部署方**, I want **为每个用户提供独立身份凭证，且认证机制保持轻量**, so that **我可以把系统交给多人使用，而不必搭建账号体系**。
2. As a **部署方**, I want **所有业务端点（含 Agent SSE 端点）在校验身份后再校验资源归属**, so that **任何用户拿到他人的 thread_id 或 artifact_id 也读不到数据**。
3. As a **部署方**, I want **Agent 工具在数据访问层同样按用户过滤**, so that **隔离不会被 Agent 侧工具调用绕过**。
4. As a **终端用户**, I want **我的上传文件与抽取结果他人不可见**, so that **我可以放心上传含商业敏感信息的报价单**。
5. As a **部署方**, I want **AI 生成的抽取代码在文件系统与网络隔离的环境中执行**, so that **恶意或出错代码不会损害宿主机和其他用户数据**。
6. As a **终端用户**, I want **模型限流/超时/5xx 时系统自动重试或切换备用模型**, so that **我不会看到 Agent 直接死掉的错误页**。
7. As a **运维人员**, I want **所有重试与回退事件写入结构化日志（模型、次数、耗时、成败）**, so that **我能排查故障，并为后续成本看板积累数据**。
8. As a **货代/采购用户**, I want **首次抽取验证通过后一键把抽取目标与脚本保存为模板**, so that **后续同格式报价单无需逐字段重新对齐**。
9. As a **货代/采购用户**, I want **上传新文件时系统判断其是否与已有模板同格式并让我确认复用**, so that **从上传到拿到验证通过的结果只需 ≤2 次交互**。
10. As a **货代/采购用户**, I want **格式不匹配或复用失败时自动回退完整抽取流程并告知原因**, so that **我永远不会拿到套错模板的错误数据**。
11. As a **部署方**, I want **模板严格归属创建者（列出/重命名/删除最小管理集）**, so that **模板这一新资产不成为新的越权面**。

## 不做什么（Out of Scope）

- ❌ 企业级 RBAC / 组织架构权限——本期只做用户级数据隔离
- ❌ OAuth / 账号注册体系——认证机制保持轻量（具体方案留待设计）
- ❌ 存量数据迁移——启用隔离时历史数据直接删除（需求方已确认）
- ❌ 多租户 SaaS 计费
- ❌ 模板市场 / 跨用户模板共享——模板仅归属创建者
- ❌ 模板字段级编辑与版本化——修改 = 另存新模板；版本化观察复用失败率后再立项
- ❌ 新文件类型（PDF/DOCX 抽取）——另行立项
- ❌ 通道（飞书/Slack）侧身份映射与权限——后续单独处理；通道接入前必须补齐，否则等于绕过隔离的侧门
- ❌ 改造 thread_id 作用域语义——它保留为用户之下的二级维度，不做废弃或重定义

## 验证方案

| 维度 | 内容 |
|------|------|
| 接口验证（R1） | 用户 A 持合法凭证请求用户 B 的会话消息 / 工件下载 / 抽取查询，全部 403；无凭证请求业务端点全部 401（`/health` 除外）；含 Agent SSE 端点 |
| 单元测试（R1） | 数据访问层按用户过滤的单测；覆盖 Agent 工具层越权读取场景 |
| 单元测试（R2） | 隔离环境内读宿主机敏感文件（如 `/etc/passwd`）、访问外网、写工作区外路径三者均失败且返回结构化错误；超内存报 OOM 类错误、超时被终止；本地开发模式下现有沙箱测试全部回归通过 |
| 接口验证（R3） | mock 模型注入 429 → 自动重试成功且用户侧无错误；主模型持续失败 → 切换备用模型完成响应且日志记录切换事件；主备全失败 → 用户收到可读「服务暂时不可用」而非栈信息 |
| E2E（R4） | 首次抽取成功 → 一键保存模板；二次上传同格式文件 → 选模板 + 确认共 ≤2 次交互拿到验证通过结果；列结构不同的文件 → 判定格式不匹配走完整流程；复用执行/验证失败 → 自动回退完整流程并向用户说明原因；模板列表/删除正确且他人不可见 |
