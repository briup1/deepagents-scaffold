SEC 02 / 07

前后对比

用户视角

BEFORE

用户上传复杂表格（多 sheet + 合并单元格）→ Agent 调用固定模板 → 脚本无法处理 → 告知用户"无法处理" → 流程终止

AFTER

用户上传复杂表格 → 主 Agent 预处理异常 → 委派子 Agent 迭代编码 → 最终脚本固化 → 验证通过 → 交付

系统视角

新增节点高亮，复用资产普通样式：

现状链路图
preview_excel → generate_extraction_code（模板渲染） → execute_extraction_code → validate_extraction_result
设计后链路图
preview_excel（增强） → normalize_upload_file → 主 Agent 路由决策
分两路：
快路径：generate_extraction_code
复杂路径：extraction_coder 子 Agent → run_extraction_script（双模式） → validate_extraction_result

    task_id: str,

迭代模式
不迁移状态、不落盘工件、计入 run_count

返回
normalized_artifact_id + source_upload_artifact_id + summary

多方案并列

维度 A: 子 Agent + 两个新工具 B: 主 Agent 内直接迭代 C: 独立微服务
复杂度中等低高
隔离性好差最好
可测试性好中好
扩展性好差好

推荐方案 A

平衡复杂度与能力，复用现有子 Agent 基础设施，隔离性足够，可测试性好。

SEC 07 / 07

最小验证

风险点
DeepAgents 子 Agent 的 permissions 字段是否支持 list[dict] 格式，以及 builder 是否能正确映射为 FilesystemPermission。
验证方法
检查 DeepAgents 源码中 SubAgent 的 permissions 处理逻辑，确认是否支持 dict 格式。
结论
待验证 需在实现阶段确认 DeepAgents permissions 接线方式。若不支持 dict 格式，退化为显式声明"子 Agent 原生文件工具不受限 + 受信用户前提"并记录为已知风险。
